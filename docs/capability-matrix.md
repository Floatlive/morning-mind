# 能力矩阵与集成前置条件

Morning Mind 的核心是本地运行、默认只读、明确暴露失败状态。下表把当前没有提供的能力逐项列出，并区分可以在不接入账户的前提下继续改进的本地能力，与必须由仓库使用者配置账户、授权或基础设施的外部集成。

| 能力 | 当前状态 | 为什么未直接启用 | 可安全完成的下一步 | 启用所需前置条件 |
| --- | --- | --- | --- | --- |
| 云日历 OAuth/API | 未集成 | 需要具体日历服务、OAuth 客户端、授权范围和令牌存储策略 | 保持 `.ics` 只读导入；已支持基础重复事件 | 用户选择服务商并提供受限 OAuth 配置，明确授权读取范围 |
| 自动化调度器 | 仓库未内置 | 本地任务调度取决于操作系统、运行目录和失败告警方式 | 可用系统调度器按固定时间运行 CLI | 选择 Windows Task Scheduler、cron 或托管调度器；定义日志、重试和并发策略 |
| 邮件/微信/短信投递 | 未集成 | 涉及对第三方发送信息、账号权限、收件人和送达语义 | 保持 `due` 只读；只有确认送达后才允许 `mark-sent` | 用户指定渠道、收件人、发送账户和失败/重试规则；通常需要密钥或 OAuth |
| 自动创建 GitHub Issue/任务 | 未集成 | 需要 GitHub 授权、目标仓库、标签/负责人规则及外部写入确认 | 继续生成本地 Markdown 和 JSON 供人工审阅 | GitHub App 或细粒度 token，最小权限、目标仓库和写入规则 |
| 云端数据库与远程同步 | 未集成 | 会改变私人账本的数据留存、访问控制和备份责任 | 继续使用本地 JSON 原子写入 | 选择存储服务、加密/备份/删除策略和迁移方案 |
| 多写入者并发锁 | 未实现 | 当前 JSON 文件按单写入者设计；跨平台可靠锁需要定义锁语义与恢复策略 | 避免多个定时任务同时写同一个状态路径 | 明确并发模型、锁超时、崩溃恢复和冲突处理；再选择文件锁或数据库 |
| LLM 推理与自动摘要 | 未集成 | 需要模型提供商、成本预算、数据发送边界和提示词审计 | 公开 RSS 内容仍可由规则差分后人工阅读 | 用户选择模型/提供商，明确哪些数据可发送、预算上限和失败降级策略 |
| 自动修改配置 | 不支持 | 自动改变订阅源、日历路径或偏好会改变个人工作流，容易产生隐性行为 | 由使用者显式编辑 JSON 配置 | 若未来支持，只能先提出变更建议，并在用户确认后写入 |
| 完整 iCalendar 兼容 | 部分支持 | RFC 5545 包含复杂时区、例外覆盖、月度规则和重复实例修改，超出当前无依赖 MVP | 已支持单次事件、每日/每周 `RRULE`、`INTERVAL`、`COUNT`、`UNTIL` 和 `EXDATE` | 需要选择完整 iCalendar 库或持续扩展解析器，并加入真实日历样本测试 |
| 订阅源历史归档 | 未实现 | 当前只保留最近一次成功快照，用于发现下一次的新条目 | `runs.jsonl` 记录每次运行摘要 | 需要定义保留期限、存储上限、清理策略和隐私边界 |
| 反馈学习 | 有限支持 | 目前仅保存已关闭决策的结果，并输出描述性统计；不自动改变偏好或配置 | 使用 `profile` 查看闭环统计，少于 10 条不作推断 | 明确定义可学习的信号、用户确认流程、可撤销性和评估指标 |

## 当前可用的本地能力

- `.ics` 今明日程读取：单次事件、每日/每周基础重复事件、间隔、次数上限、截止日期与排除日期。
- 公开 RSS/Atom 读取与快照差分；首次成功读取建立基线。
- 本地 Markdown 简报、状态 JSON、只追加运行日志。
- 决策记录、内容指纹去重、到期查询、只读晨报回访、人工送达确认、人工关闭与描述性统计。

## 非目标

本仓库不会绕过 OAuth、伪造日历数据、猜测联系人、替用户发送对外消息，或将“无法读取”写成“没有内容”。对于涉及账户授权、第三方写入、密钥或私人数据外传的集成，应在具体启用前单独确认。
