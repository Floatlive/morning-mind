# Codex 自动化文字推送

这个集成沿用使用者已有的本地 Codex 定时任务。任务按配置时区运行 `scripts/morning_dual.py`，读取输出的 Markdown 文件，并把简报正文作为任务最终回复发到该任务对话。不要在仓库中保存真实日历、账本、状态文件或自动化的私人路径。

## 任务步骤

1. 运行前确认固定状态文件存在且可读；缺失时报告失败，不重新建立基线。
2. 以配置时区的当天日期执行脚本，传入固定的 `--config`、`--state`、`--output`；如已配置决策账本，也传入只读的 `--ledger`。
3. 核对退出码、JSON 摘要和生成的 Markdown。成功时在任务最终回复中直接呈现简报正文，包括今明日程、监控新增、逐源失败和决策回访，不只回复文件路径。
4. 失败时在任务最终回复中写明失败阶段和受影响的数据源；不得把失败解释成无变化，也不得自动重建状态文件或调用 `mark-sent`。
5. 在回复中注明：`投递渠道：Codex 自动化任务对话；设备通知显示与用户阅读未确认。`

## 投递状态

`scripts/morning_dual.py` 的 `status` 描述输入读取与简报生成，不是送达状态。Codex 任务的最终回复由平台发布，脚本无法获得发布回执。因此这套配置提供定时文字结果，但不能声称手机、邮件、Windows 通知或用户阅读已经确认。

当前脚本会在写出简报后提交订阅源快照。如果之后的 Codex 回复失败，下一次运行可能无法再次识别本次新增。不要通过重复运行脚本来声称已经重试投递；若要实现可靠的待投递队列，应先接入能返回发送结果的渠道，再以回执为条件提交快照，并保存失败待重试记录。
