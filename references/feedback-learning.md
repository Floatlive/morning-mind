# Bounded feedback learning

这里的“学习”是维护少量本地偏好记忆并复盘结果，不会训练或修改底层模型。

## Evidence

只接受以下学习信号：

- 用户明确纠正晨报，或明确说某项有用/无用。
- 用户确认 B 记录的实际结果。
- 用户明确说明今后都应采用的偏好。

沉默、推测出来的日历行为、一次性限制都不是长期偏好。不要把完整日历事件文本复制到学习文件。

## Update cycle

1. 收到纠正后，记录日期、工作流、类别和最少必要依据；避免保存敏感日程细节。
2. 单次信号只作为观察。同一偏好在至少三次不同场景被明确确认后，才提出简短的偏好调整建议。
3. 修改配置、名单、日历范围、阈值、收件人、时间或投递方式前先征求确认。获准后写入独立的偏好/配置文件，并记录确认日期。
4. 定期概括已确认偏好、候选偏好和未知项；未经确认不得宣称已学会。

## B outcome review

- 记录后保持用户原始预期和把握度不变，不为迎合结果改写历史。
- 由用户将结果标为 `hit`、`partial` 或 `miss`，并附简短说明；不把模糊结果强行二分。
- 少于 10 条已关闭记录时只逐条呈现结果。达到 10 条后可做描述性汇总，但必须显示样本量和领域数量，不作因果判断。
- 置信度校准需要多个把握度区间的样本；样本少或分布严重失衡时，不声称已校准或存在稳定偏差。除非用户批准评分规则，`partial` 独立统计。
- 画像仅供参考，不得静默改变未来把握度或决策。

## Suggested learning-state file

学习状态与工作流配置、决策账本分开存放。初始结构见 `assets/learning_state.template.json`。原子写入，仅保留有用的最少文本；用户可查看、编辑或清空。
